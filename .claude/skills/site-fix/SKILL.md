# site-fix — 보수

## 절차

1. **재현.** 증상을 직접 확인한다: `verify` 출력, 미리보기 브라우저(해당 폭·테마), 콘솔/네트워크 오류.
   재현이 안 되면 고치지 말고 사용자에게 환경(기기, 브라우저, 페이지 주소, 스크린샷)을 묻는다.
2. **원인.** 어느 파일 어느 줄 때문인지 특정한다. git이 있으면 `git log -p -- <파일>`로 언제 바뀌었는지 본다.
   원인을 한두 문장으로 사용자에게 설명할 수 있어야 다음 단계로 간다.
3. **최소 수정.** 원인만 고친다. 김에 리팩터링하지 않는다. 고칠 위치가 데이터면 site-edit 규칙,
   구조·스타일이면 site-build 규칙(토큰만 사용)을 따른다.
4. **재발 방지(선택).** 같은 문제가 기계로 잡히는 종류면 `tools/check-site.mjs`에 검사를 추가할지 제안한다.
5. **검증.** `npm --prefix site run verify` 통과 + 1단계 재현 방법으로 증상이 사라졌는지 확인.
6. `docs/maintenance-log.md`에 "보수" 항목: 증상 · 원인 · 수정 · 검증.

## 하지 말 것
- 검사를 끄거나 예외 처리로 오류를 숨기기(정말 오탐이면 사용자에게 알리고 스크립트를 고친다).
- 원인 모른 채 여러 군데 바꿔보기.
